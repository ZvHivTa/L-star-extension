# Work Log - 2026-05-03

## 项目定位

当前项目围绕一个基于 L* 思想的主动学习算法展开。目标不是传统地先学习 regular language 的 minimal DFA，再把 DFA 后处理转换为 syntactic monoid；而是通过扩展观察表，直接学习带有 syntactic monoid 结构约束的 DFA 表示。

核心观察表形式为：

```text
T[i, p, s] = MQ(p + i + s)
```

其中：

- `I`：主区代表元，表示当前候选状态/候选 monoid 元素。
- `P`：左语境集合，用于捕捉 syntactic congruence 的左乘行为。
- `S`：右语境集合，用于区分语言接受行为。

算法的三类 refinement：

- 闭合拦截：发现 `I · Sigma` 中有新 row pattern，将其提拔进 `I`。
- 反例拦截：EQ 返回语言反例，用 Rivest-Schapire breakpoint 策略补充 `S`。
- 代数拦截：语言 EQ 通过后，检查左右语境一致性；若发现 boundary 和 representative 在某个左/右语境下被区分，则补充 `P`。

### 1. Debug 输出改为 DOT

### 2. 性能测试时关闭内部日志

发现 `debug_mode=False` 时，学习过程仍会打印闭合拦截、反例拦截、代数拦截等日志，这些 `print` 会计入 integrated learner 的运行时间。

处理方式：

- 给 `Learner` 增加 `verbose` 参数。
- 所有内部日志统一走 `self.log(...)`。
- `benchmark.py` 中设置 `verbose=debug_mode`。

现在：

```python
benchmark(regex, debug_mode=False)
```

会关闭 learner 内部过程日志和 debug 快照，计时更干净。

### 3. Baseline 终点补齐为 Monoid DFA

原 baseline 是：

```text
Classic L* -> learned DFA -> transition monoid elements
```

但 transition monoid elements 只是 `set[tuple]`，不是自动机对象。为了让 baseline 的最终产物更接近新算法的 DFA 表示，补充了 monoid-induced DFA 构造。

现在 baseline 是：

```text
Classic L*
  -> learned DFA
  -> transition monoid elements
  -> Cayley-style monoid DFA
```

新增函数：

- `compute_transition_monoid_data(...)`
- `build_monoid_dfa(...)`

baseline 总时间现在为：

```text
L* 学 DFA 时间 + DFA 转 monoid 时间 + monoid DFA 构造时间
```

报告中新增：

- `Monoid DFA 状态数`
- `阶段3 (Monoid DFA)`
- `阶段1+2+3 总耗时`

### 4. 新算法查表性能优化

为 `Learner` 增加了多层缓存：

- `row_cache`：缓存 `get_row(i)` 的结果，避免重复构造 row tuple。
- `sorted_p_cache`
- `sorted_s_cache`
- `sorted_i_cache`
- `right_extensions_cache`

当 `P/S/I` 变化时，通过 `invalidate_context_cache(...)` 清理相关缓存。

同时优化：

- `build_state_maps()` 复用 `row_representatives()`，避免重复扫描 `I`。
- `representative_for_row()` 和 `row_representatives()` 使用排序缓存。

### 5. Oracle BFS 数据结构优化

`Oracle` 和 `ClassicOracle` 中找最短反例的 BFS 队列从：

```python
queue = [(initial_state, "")]
queue.pop(0)
```

改为：

```python
queue = deque([(initial_state, "")])
queue.popleft()
```

避免 `list.pop(0)` 的线性移动开销。

### 6. 代数自检复用已有观察表

`check_boundary_consistency()` 中原本直接查询：

```text
MQ(left + boundary + suffix)
MQ(left + representative + suffix)
```

现在通过 `lookup_context_membership(...)` 优先复用已有表格信息：

```text
T[middle, left, suffix]
T[left + middle, "", suffix]
```

只有表中没有对应信息时，才 fallback 到真正的 MQ。

并且在一次 `ensure_monoid_consistency()` 内部增加局部 `context_cache`，避免同一轮自检中重复查同一个：

```text
(left, middle, suffix)
```

### 7. 跳过 P-refinement 后的无用 EQ

讨论确认：当语言 EQ 已经通过后，如果后续只是代数自检失败并补充 `P`，没有新增 `S`，则不需要再次做语言 EQ。

新增状态：

```python
self.language_confirmed
self.skipped_eq_count
```

现在控制流为：

```text
如果 language_confirmed == False：
  做 EQ

如果 EQ 返回反例：
  补 S
  language_confirmed = False

如果 EQ 返回 None：
  language_confirmed = True
  进入代数自检

如果代数自检失败：
  补 P
  保持 language_confirmed = True

下一轮 closed 后：
  跳过 EQ
  直接进入代数自检
```

benchmark 报告中新增：

```text
跳过 EQ 次数
```

验证样例：

```text
regex = ()|(a|b)|(a|b)(a|b)|(a|b)(a|b)(a|b)b*
```

优化前 integrated learner：

```text
EQ = 7
```

优化后：

```text
EQ = 4
跳过 EQ = 3
结果正确 = True
```

## 后续可继续优化方向

### 1. ClassicLearner row cache

为了让 baseline 更公平，可以给经典 L* 也加：

```text
row_cache
sorted_E_cache
```

当 `E` 变化时清空 row cache。

### 2. 代数拦截时是否立即补 I

当前策略仍是 lazy style：

```text
代数自检发现 boundary 被代表元错误合并
-> 补 P
-> 下一轮闭合检查再发现新 row
```

可选 eager 策略：

```text
补 P 的同时直接把 boundary 加入 I
```

这可能减少一次闭合拦截轮次，但属于策略层优化，今天暂未改。

### 3. benchmark 多轮统计

当前 benchmark 是单次运行，毫秒级样例波动明显。后续可增加：

```text
repeat = 10 / 30
输出 min / median / mean
```

用于更稳定的实验结论。

### 4. 批量实验时关闭最终表导出

`observation_table.txt` 导出不计入 reported time，但批量跑很多样例时仍会拖慢总实验耗时。可以增加参数：
