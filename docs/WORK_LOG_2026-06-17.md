# Work Log - 2026-06-17

## 今日定位

今天把项目从多条实验分支收敛回当前可证明正确的主线，并把理论证明中必须的
Right Consistency refinement 接入 `Learner`。

这次工作的核心结论是：

```text
Closedness
  -> Right Consistency
  -> Hypothesis Acceptor
  -> Equivalence Query
  -> Monoid Consistency
```

Right Consistency 负责保证后缀行等价在右乘字母后仍稳定，从而使 acceptor 的右作用定义可靠。Monoid Consistency 继续负责 EQ 通过后的左语境代数自检。

## 理论状态

当前证明链已经整理为：

1. 定义 path representative function `rho(w)`：输入 `w` 后 acceptor 到达状态的 `I` 中标签。
2. 证明若 acceptor 通过 EQ，则 `w` 与 `rho(w)` suffix-equivalent。
3. 用 Right Consistency 和 EQ 推出 suffix equivalence 蕴含 Myhill-Nerode 式的任意右语境等价。
4. 将该结论用于每个左语境，推出 status equivalence 对右乘稳定。
5. 归纳证明每个 `w` 都与 `rho(w)` status-equivalent。
6. 由 separability 得到 status equivalence 与 acceptor 状态相等一致。
7. 在此基础上，Monoid Consistency 的正确性证明不再依赖未证明的跳步。

## Right Consistency 实现

在 `learner.py` 中新增：

```python
get_suffix_row(i)
ensure_right_consistency()
```

`get_suffix_row(i)` 只读取左语境为空串时的经典后缀行：

```text
T(i, epsilon, s), s in S
```

`ensure_right_consistency()` 检查：

```text
i ==_S j  but  ia !=_S ja
```

若发现违反，找到区分后缀 `s`，加入：

```text
a + s
```

到 `S`。

因此 refinement 职责变为：

```text
Closedness failure        -> add to I
Right Consistency failure -> add to S
EQ counterexample         -> add to S
Monoid Consistency failure-> add to P
```

新增统计项：

```text
right_consistency_refinements
```

并在 benchmark 报告中输出。

## 关键验证

### 旧反例 `(aa|bbb)*`

Baseline：

```text
Minimal DFA states : 4
Monoid size        : 23
Monoid DFA states  : 23
```

`post_check`：

```text
Rows: 47 (Upper I: 23 | Lower Ext: 24)
Cols: 16 (P: 4 * S: 4)
Right consistency refinements: 0
EQ count: 4
Skipped EQ count: 3
```

`promote_to_p`：

```text
Rows: 47 (Upper I: 23 | Lower Ext: 24)
Cols: 92 (P: 23 * S: 4)
Right consistency refinements: 3
EQ count: 1
I-promoted-to-P count: 22
```

解释：

- 两个策略最终都达到 `I = 23`，与 baseline 的 monoid size 对齐。
- `post_check` 通过 EQ 反例逐步加入 `S = {epsilon, a, b, bb}`，再由 Monoid Consistency 补 `P = {epsilon, a, b, bb}`。
- `promote_to_p` 因为每个新 `I` 都同步加入 `P`，所以 `P = I`，表格更宽；它通过 Right Consistency 较早加入 `a,b,bb`，因此 EQ 次数更少。
